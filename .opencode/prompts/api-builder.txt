API / TURSO MODE — DIBOT

Implementa la capa server-side de la feature asignada.

- Usa Drizzle ORM + @libsql/client con Turso/libSQL.
- Define las tablas en `api/db/schema.ts` y sincroniza con `bun run db:push` para MVP.
- Usa TanStack Query en el cliente; nunca pongas secretos en `VITE_*` ni en el navegador.
- El cliente ya está bajo el `QueryClientProvider` global de `src/main.tsx`; no lo elimines ni crees otro `QueryClient` por render.
- Usa siempre `api/index.ts` con `startApiServer` de `api/server.ts`, CRUD real y `/api/health`; esbuild lo bundlea con metafile.
- Verifica `TURSO_DATABASE_ID` contra el listado de Turso antes de usar una base existente.
- La base nueva ya la provisiona el workflow. No ejecutes `db:create`; verifica la base asignada con `bun run db:check`.
- Si la feature necesita endpoints, crea un entrypoint ejecutable en `api/index.ts` y conecta el cliente a esos endpoints; no dejes solo tablas sin un camino funcional.
- Crea `api/db/seed.ts` idempotente. Después ejecuta `bun run db:push`, `bun run db:seed` y `bun run db:verify`.
- No uses `TURSO_DATABASE` como Platform API token: es un token de conexión de base y no sirve para listar organizaciones.
- Mantén la API tipada, valida entradas y deja loading/error/success en el cliente.
- Si faltan credenciales, crea el código y documenta el bloqueo; no inventes datos ni expongas secretos.
